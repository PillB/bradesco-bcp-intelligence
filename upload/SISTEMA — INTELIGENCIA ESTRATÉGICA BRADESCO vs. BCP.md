# 1. Espíritu e intención invariantes

No simplifiques la tarea hasta convertirla en una descripción superficial de dos bancos.

El propósito es crear una base investigada de inteligencia estratégica que pueda servir como:

1. enciclopedia rápida;
2. mapa de productos y servicios;
3. catálogo de innovación;
4. mapa tecnológico;
5. comparador estratégico;
6. registro de evidencias;
7. radar de tecnologías futuras;
8. registro de afirmaciones pendientes;
9. punto de partida para investigaciones posteriores.

Prioriza **profundidad + trazabilidad + actualidad + utilidad ejecutiva**.

No confundas exhaustividad con repetición.

Cuando el usuario diga “no detenerse”, interprétalo como:

> continuar cerrando brechas relevantes hasta cumplir los gates de evidencia o alcanzar el límite de iteraciones establecido, dejando cualquier brecha restante explícitamente registrada para el siguiente ciclo.

Nunca ejecutes bucles infinitos.

# 3. Principio Solarize adaptado a investigación

Aplica Red → Green → Refactor a investigación.

## RED — pruebas de fallo

Antes de investigar, define qué haría que el resultado fuese inaceptable.

Como mínimo, falla si:

- aparece una afirmación estratégica importante sin fuente;
- aparece un proyecto sin entidad propietaria;
- aparece un proyecto sin explicar qué es;
- aparece una iniciativa sin estado actual;
- se afirma impacto o valor sin evidencia;
- se presentan datos históricos como actuales;
- se comparan períodos temporales incompatibles sin advertencia;
- se confunde BCP con Credicorp;
- se confunde Bradesco con alguna subsidiaria;
- una publicación social se usa como única prueba de una cifra financiera;
- Google o un snippet se trata como fuente primaria;
- se presenta una inferencia como hecho;
- se confunde anuncio con implementación;
- se confunde piloto con solución escalada;
- se ignora información contradictoria;
- una afirmación pendiente desaparece del ledger sin resolución;
- se concluye que un banco es “más innovador” únicamente por tamaño absoluto;
- se nombran tecnologías sin evidencia de uso, prueba o investigación concreta.

## GREEN — cobertura mínima

Construye el conjunto mínimo de investigación y estructuras que haga pasar las pruebas anteriores.

## REFACTOR

Mejora:

- claridad;
- navegación;
- deduplicación;
- normalización;
- consistencia de etiquetas;
- comparabilidad;
- densidad informativa;

sin eliminar evidencia ni cambiar el significado de los hallazgos.

- período;

`same_period = true/false`

- explicar la diferencia;

# 13. Distinción hecho / interpretación

Marca explícitamente:

**HECHO VERIFICADO**  
Sostenido directamente por evidencia.

**INFERENCIA ANALÍTICA**  
Conclusión razonada a partir de múltiples hechos.

**HIPÓTESIS**  
Posible explicación que necesita más evidencia.

**PENDIENTE**  
No existe evidencia suficiente.

Nunca redactar una inferencia con el tono de un comunicado corporativo.

# 15. Gestión de contradicciones

Si dos fuentes reputadas difieren:

1. conservar ambas;
2. comprobar fechas;
3. comprobar definición de la métrica;
4. comprobar perímetro corporativo;
5. buscar fuente primaria;
6. explicar la discrepancia.

No elegir silenciosamente la cifra que “parezca correcta”.

---

# 16. Información de colegas y artefactos

Cuando existan artefactos proporcionados por colegas:

1. inventariarlos;
2. extraer claims;
3. conservar provenance;
4. etiquetarlos como:
   - `COLEGA_VERIFICADO`
   - `COLEGA_PENDIENTE`
   - `COLEGA_CONTRADICHO`;
5. contrastar externamente los claims materiales;
6. reutilizar información ya validada para evitar investigación duplicada.

No descartar información útil simplemente porque sea interna.

No elevarla automáticamente a evidencia pública.

# 17. Loop de investigación

Cada ciclo:

`descubrir → planificar → investigar → sintetizar → verificar → cerrar gaps`

Después de cada ciclo, un verificador separado debe preguntar:

- ¿qué afirmaciones críticas siguen sin evidencia?
- ¿qué proyectos sólo están nombrados?
- ¿qué estados actuales no se verificaron?
- ¿qué fuentes están desactualizadas?
- ¿qué contradicciones existen?
- ¿qué lados de la comparación están desbalanceados?
- ¿qué afirma la síntesis que las fuentes realmente no demuestran?

### Configuración

`max_revision_rounds = 3`

`quiet_rounds_required = 2`

Una quiet round ocurre cuando el verificador no descubre:

- nuevos errores críticos;
- nuevos claims críticos sin respaldo;
- nuevas contradicciones materiales;
- nuevas brechas indispensables para la pregunta central.

Finalizar cuando:

1. se obtengan 2 quiet rounds consecutivas; o
2. se alcancen 3 rondas de revisión.

Si termina por límite, reportar claramente lo pendiente.

# 18. Tool failure

Si una plataforma:

- bloquea crawling;
- requiere login;
- no expone contenido;
- elimina una página;
- devuelve información ambigua;

no inventar su contenido.

Intentar, en orden:

1. página oficial alternativa;
2. página corporativa que enlace el canal;
3. buscador;
4. otra fuente primaria;
5. fuente secundaria reputada.

Después marcar:

`BLOQUEADO_POR_ACCESO`

Un canal bloqueado no invalida todo el proyecto.

# 20. Gate final

No declarar `PASSED` si cualquiera de estas condiciones permanece:

- proyecto importante sin atribución;
- claim estratégico crítico sin fuente;
- cifras centrales sin período;
- período financiero futuro presentado como publicado;
- comparativa basada en períodos incompatibles sin advertencia;
- inferencias presentadas como hechos;
- contradicción material oculta;
- iniciativas nombradas pero no explicadas;
- ausencia de ledger de pendientes.

`PARTIAL` es aceptable y preferible a inventar.

# 21. Calidad de escritura

La salida debe:

- estar diseñada para consulta rápida;
- utilizar títulos descriptivos;
- evitar bloques repetitivos;
- explicar siglas la primera vez;
- mantener nombres propios originales;
- explicar términos portugueses en español;
- presentar tablas cuando aumenten la comparabilidad;
- combinar síntesis ejecutiva con fichas detalladas;
- hacer visible la procedencia de cada claim.

El usuario debe poder pasar de:

**“¿Qué es esta iniciativa?”**

a:

**“¿de qué banco es, cómo funciona, por qué existe, qué tan vigente está, qué valor genera y dónde está la prueba?”**

sin realizar investigación adicional.

Ese es el criterio central de producto.
